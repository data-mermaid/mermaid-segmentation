# AGENTS.md rule sources

This file records where each rule in [`AGENTS.md`](../AGENTS.md) comes from, the exact source text,
and how the rule's wording and strength differ from that text. Agents don't need it while they
work. Read it before you add, change or remove a rule.

## How to add or change a rule

1. Fetch the source again. Copy the exact text; don't quote from memory. Pin a GitHub raw link to
   the commit you fetched (`gh api repos/<owner>/<repo>/commits/main --jq .sha`).
2. Lift the source text word for word where it stands on its own. Otherwise paraphrase it.
3. Decide the rule's force. Only a rule that says must, never or always is hard (`AGENTS.md` 0.2);
   every other rule is judgement (0.4). Adding one of those words to a lifted rule hardens it.
4. Add or update the rule's row below: section and item, short form, source (name, URL, license),
   exact source text, delta, and reason.
5. Choose one delta:
   - `verbatim`: the source text, unchanged.
   - `adapted-wording`: reworded for this repository (tool names, our stack) at the same strength.
   - `hardened` or `softened`: the strength changed on purpose. Give a one-line reason.
   - `repo-specific`: no outside source. The reason names the repository fact behind the rule.
6. Record every dropped qualifier ("whenever possible", "unless", "prefer", or a scope such as
   "when a modular one exists") in the reason, even when the delta is `adapted-wording`.
7. For copyrighted papers, cite the title and heading only. Don't quote body text.
